# 决策：项目架构设计

- **日期**: 2026-05-04
- **主题**: 人与 Agent 共存项目的目录架构
- **决策人**: agent + human
- **状态**: confirmed

## 背景

用户希望建立一个 Agent 和人类可以共存、协作的项目。需要解决的核心问题：
1. Agent 需要详细、结构化的信息来工作
2. 人类只想看概要、不想被细节淹没
3. 代码和核心文档是共享资产
4. 需要一套自动化的信息流转机制

## 决策内容

采用**双空间 + 共享空间**的三层架构：

```
project-root/
├── .agent/         # Agent 专属空间（详细资料、记忆、计划）
├── human/          # 人类专属空间（概要、仪表板、交互）
├── src/            # 共享：源代码
├── docs/           # 共享：技术文档
├── scripts/        # 共享：工具脚本
└── config/         # 共享：配置文件
```

### 空间职责

| 空间 | 归属 | 内容 | 信息密度 |
|------|------|------|---------|
| `.agent/` | Agent | 结构化记忆、详细计划、决策日志、工具 | 高 |
| `human/` | 人类 | 概要文档、仪表板、交互界面、报告 | 低 |
| `src/` 等 | 共享 | 代码、配置、架构文档 | 中 |

### 入口文件

- Agent 第一入口：`AGENTS.md`
- 人类第一入口：`README.md`

## 备选方案

- **方案A（未采纳）**: 单一目录，用文件命名区分（如 `HUMAN_README.md`、`AGENT_SPEC.md`）
  - 缺点：空间混杂，Agent 和人类的内容会互相干扰
- **方案B（已采纳）**: 物理分离为不同目录
  - 优点：职责清晰、权限边界明确、易于自动化同步

## 影响

- 目录结构需要一次性建立
- Agent 必须遵守空间归属规则
- 需要开发同步脚本 `agent_sync.py`
- 人类不应直接修改 `.agent/` 中的文件
